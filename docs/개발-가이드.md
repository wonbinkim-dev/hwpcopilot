# 개발·테스트·빌드

## 개발 환경

- Windows x64
- Node.js 22.12 이상 및 npm
- 실제 문서 편집 검증에는 자동화 기능을 지원하는 한글 데스크톱
- 외부 AI 호출에는 해당 제공자의 API 키

모든 명령은 `package.json`이 있는 프로젝트 루트에서 실행합니다. PowerShell의 npm 스크립트 실행 정책 문제를 피하기 위해 예시는 `npm.cmd`를 사용합니다.

## 설치와 실행

```powershell
npm.cmd ci
npm.cmd start
```

의존성이 이미 설치되어 있다면 `npm.cmd start`만 실행합니다. 현재 로컬 작업 경로에서는 먼저 다음 명령으로 이동할 수 있습니다.

```powershell
cd D:\dev\hwpcopilot
```

GitHub에서 내려받은 프로젝트는 자신이 내려받은 폴더로 이동하세요. `D:\dev` 경로가 필수인 것은 아닙니다.

| 명령 | 역할 |
| --- | --- |
| `npm.cmd start` | 데스크톱 패널 실행 |
| `npm.cmd run start:web` | 개발용 웹 화면 실행, `http://127.0.0.1:3210` 접속 |
| `npm.cmd test` | 자동 테스트 |
| `npm.cmd run test:desktop` | 모의 AI·문서와 테스트 창으로 데스크톱 검증 |
| `npm.cmd run dist` | Windows x64 포터블 EXE 빌드 |
| `npm.cmd run dist:installer` | Windows x64 설치형 EXE 빌드 |

웹 화면의 기본 포트가 사용 중이면 실행 전에 `$env:PORT = '3211'`로 변경할 수 있습니다.

## 코드 구조

| 위치 | 역할 |
| --- | --- |
| `src/desktop/main.js` | Electron 시작점, 창 관리, IPC, 트레이 |
| `src/desktop/launch.cjs` | 개발 실행기, IDE의 Electron 환경변수 분리 |
| `src/desktop/preload.cjs` | 화면에 허용된 IPC API 노출 |
| `src/desktop/docking.js`, `tracker.js` | 패널 배치 계산과 창 추적 연결 |
| `src/desktop/profiles.js` | 키를 제외한 연결 설정 저장 |
| `src/document-service.js` | 읽기·생성·적용·저장 흐름과 중복 쓰기 차단 |
| `src/providers.js` | AI API별 요청·응답 어댑터 |
| `src/usage.js` | 제공자별 토큰 사용량과 한도 헤더 정규화 |
| `src/public/chat-state.js` | 누적 사용량 상태와 최근 대화 선택 |
| `src/bridge.js` | Node.js와 PowerShell 간 JSON 메시지 전달 |
| `src/native/hwp-core.ps1` | 한글 COM 연결과 실제 문서 편집 |
| `src/native/window-tracker.ps1` | Windows 창 위치·최소화·전경 상태 추적 |
| `src/public/` | 사용자 화면, 스타일, 아이콘 |
| `src/hwpcopilot.js` | 개발용 로컬 HTTP 서버 |

데스크톱은 제한된 IPC를 통해 문서 서비스를 호출합니다. 브라우저 개발 모드는 같은 서비스를 HTTP로 호출하며 `127.0.0.1`에서만 수신합니다.

## 검증

```powershell
npm.cmd test
npm.cmd run test:desktop
```

자동 테스트는 API 형식·응답 처리, 문맥 범위, 문서 서비스, 로컬 접근 제한, 배치 좌표, 프로필의 키 비저장을 확인합니다. 데스크톱 테스트는 모의 AI와 문서를 사용하고, 테스트 창으로 이동·최소화·복원·원래 배치 복구를 확인합니다.

테스트 결과는 `artifacts/desktop-smoke.json`, 화면은 `artifacts/desktop-preview.png`에 생성됩니다.

실제 한글의 새 테스트 문서로 검증하려면 다음 명령을 사용합니다.

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File test\hwp-native-smoke.ps1
```

이 테스트는 별도의 빈 한글 문서에서 읽기·삽입·한국어 선택 교체·커서 변경 감지·되돌리기를 확인합니다. 기존 보고서는 열지 않으며, 정확히 일치하는 테스트 문서만 정리합니다. `ExecutionPolicy` 옵션은 해당 PowerShell 프로세스에만 적용합니다.

## 빌드 결과

```powershell
npm.cmd run dist
```

현재 버전의 포터블 결과는 `bin/HWP-Copilot-0.3.1-x64.exe`입니다. 설치형은 `npm.cmd run dist:installer`로 만들며 `bin/HWP-Copilot-Setup-0.3.1-x64.exe`가 생성됩니다. 파일 이름의 버전은 `package.json`을 따릅니다.

빌드한 포터블 EXE 자체를 검증하려면 다음 명령을 사용합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File test\packaged-smoke.ps1
```

배포 EXE 검증은 모의 문서와 AI를 사용합니다. 결과는 `%TEMP%\HWP-Copilot-smoke`에 저장합니다. 버전을 바꾸면 테스트 스크립트의 대상 EXE 이름도 맞춰 주세요.

Electron 빌드에는 `src/`의 앱 코드와 화면을 포함하고, `src/native/`는 별도 리소스로 복사합니다. 팀원 PC에는 Node.js가 필요하지 않습니다. 코드 서명 인증서는 프로젝트에 포함되어 있지 않습니다.

## 호환성과 편집 제한

한글 연결은 등록된 `HWPFrame.HwpObject` COM 인터페이스를 사용합니다. x64 PowerShell에서 32비트 한글의 등록 정보를 찾을 수 있도록 두 레지스트리 보기를 확인합니다. 한국어 텍스트는 `UNICODE` 형식으로 읽습니다.

`open` 요청은 연결 후 한글의 `FileOpen` 동작으로 파일 선택·저장 확인창을 표시하고, 성공하면 문서를 읽어 새 revision을 반환합니다. 파일 선택 취소·열기 실패 때도 이전 revision과 네이티브 baseline을 만료합니다. 별도로 열어 둔 다른 COM 인스턴스에 연결하지 않습니다. `test/hwp-open-smoke.ps1`은 실제 문서 없이 모의 객체로 열기·취소·실패 처리를 확인합니다. 실제 파일 선택창 조작은 수동 확인 대상입니다. [한컴 자동화 동작 목록](https://raw.githubusercontent.com/hancom-io/devcenter-archive/main/hwp-automation/ActionObject.pdf)

적용 직전에 문서 식별자·창·경로·본문·선택 텍스트·커서와 선택 범위를 비교합니다. 서식만 바뀐 경우는 감지하지 못합니다. 문맥은 150,000자, 적용 본문은 200,000자 제한이며, 한글·AI 요청 대기 제한은 120초입니다. 시간 초과된 쓰기는 자동 재시도하지 않습니다.

실제 한글 2018 편집을 검증했으며, 다른 한글 버전·유료 API 실호출·저장 대화상자 동작은 별도 확인 대상입니다.
